KAIKEI

書き換えられていないことの確かめ方

解経が「後から書き換えていない」ことを、解経を信じずに確かめる方法です。

なぜこれが要るのか

解経は「値を後から書き換えない」と言っています。ですが、言っているだけでは根拠になりません。 日付ごとの固定版も、その元になっている記録も、解経の手元にあります。運営者がその気になれば書き換えられます。

そこで、解経の外側に証拠を置いています。 下の手順で、解経を信じずに確かめられます。

手順1: その日の記録が、その日より前に存在していたことを確かめる

日付ごとの固定版には、OpenTimestamps の証明ファイル（.ots）を添えてあります。これは、そのファイルの指紋を Bitcoin のブロックに刻んだ記録です。解経にも、証明を作った側にも、後から書き換えられません。

pip install opentimestamps-client
curl -O https://kaikei-media.github.io/data/2026-09-01/kaikei.csv
curl -O https://kaikei-media.github.io/data/2026-09-01/kaikei.csv.ots
ots verify kaikei.csv.ots

「Success! Bitcoin block N attests existence as of ...」と出れば、そのCSVがその日時より前に存在していたことが確かめられます。1文字でも違うファイルでは通りません。

Bitcoin のブロックに入るまで数時間かかります。打った直後の日付は、まだ「未確定」と出ることがあります。

手順2: 途中の日が抜き取られていないことを確かめる

1日ぶんの証明だけでは、都合の悪い日をまるごと消したかどうかはわかりません。そこで、日ごとの記録を鎖にしてあります。

各日の記録は「その日のCSVの指紋」と「前日の鎖の値」を合わせてもう一度ハッシュを取った値を持ちます。1日でも中身を変えるか、1日でも抜き取ると、それ以降の鎖が全部合わなくなります。

curl -O https://kaikei-media.github.io/data/chain.jsonl

各行の chain が sha256(prev + sha256) になっているかを確かめてください。最初の行の prev は 0 が64個です。

これで証明できること・できないこと

証明できること: この内容が、この時刻より前に存在していたこと。そして、後から書き換えられていないこと。

証明できないこと: 内容が正しいこと。嘘を刻めば、嘘がそのまま永久に残るだけです。だからすべての値に一次資料のURLを付けています。確かめるべきはそちらです。

これも証明できません: 解経が、都合の悪い値を最初から載せなかったかどうか。タイムスタンプは「載せたもの」しか守れません。これへの備えは技術ではなく、流れが変わる合図を先に決めて公開しておくという設計のほうです。見立てが外れる側の合図（逆方向の合図）も同じ場所に並べてあります。

自分でチェーンに書き込まない理由

自前のウォレットから直接書き込む方式は採っていません。入金の経路から匿名運営の身元が割れるためです。OpenTimestamps は手数料も、ウォレットも、秘密鍵も要りません。得られる証明は同じです。
